## 1. Resumen ejecutivo

Se ejecutó Lighthouse con la categoría **Accessibility** sobre la página de Inicio del frontend de EcoLogística Huancayo.

| Indicador | Resultado observado |
|---|---:|
| Puntuación de accesibilidad de Lighthouse | **100/100** |
| Auditorías automáticas aprobadas | **18** |
| Auditorías automáticas fallidas | **0** |
| Comprobaciones sugeridas para revisión manual | **10** |
| Auditorías no aplicables a esta página | **48** |
| URL evaluada | `http://localhost:5173/` |
| Versión de Lighthouse | `13.4.1` |

El reporte HTML descargado incluye el resultado estructurado de Lighthouse y confirma una puntuación de accesibilidad de `1.0`, equivalente a **100/100**. No se registraron auditorías automáticas fallidas para esta página en esta ejecución.

**Alcance y limitación:** este resultado corresponde únicamente a la carga inicial de la página de Inicio. No es un resultado global de todas las vistas (Flota, Clientes, Conductores, Pedidos y Rutas), y no demuestra por sí solo conformidad completa con WCAG 2.2 nivel AA. Lighthouse advierte que las pruebas automáticas detectan solo una parte de los posibles problemas y recomienda una revisión manual.

## 2. Resultado de accesibilidad por principios WCAG

Lighthouse entrega una puntuación general de accesibilidad para la página analizada; no entrega porcentajes independientes para cada uno de los cuatro principios WCAG. Por ello, no se asignan porcentajes por principio a partir de este único informe.

| Principio WCAG | Evidencia observada en el informe | Estado de la evaluación |
|---|---|---|
| **Perceptible** | La auditoría automática de contraste de color pasó en la página de Inicio. Esto no equivale a revisar toda la presentación, imágenes, textos alternativos y ampliación en todas las vistas. | Parcialmente revisado; falta comprobación manual y de otras vistas. |
| **Operable** | La auditoría automática de tamaño/espaciado de objetivos táctiles pasó. Lighthouse dejó como revisión manual el foco de controles, orden de tabulación, indicación del estado y trampas de foco. | Parcial; comprobaciones manuales pendientes. |
| **Comprensible** | El informe confirma que el documento tiene un título y que declara un idioma válido. No evalúa por completo la claridad de instrucciones, errores de formularios o previsibilidad de todas las interacciones. | Parcialmente revisado; falta prueba funcional/manual. |
| **Robusto** | Pasaron las comprobaciones automáticas relacionadas con atributos ARIA válidos y permitidos, y existe un punto de referencia principal (`main`). Lighthouse recomienda revisar manualmente roles y etiquetas de controles personalizados. | Parcial; comprobaciones manuales pendientes. |

## 3. Auditorías automáticas aprobadas

El reporte muestra 18 auditorías aprobadas. Entre las comprobaciones relevantes se encuentran:

- Atributos ARIA compatibles con los roles y con valores válidos.
- Controles de tipo botón con nombre accesible.
- Contraste de color suficiente en los elementos evaluados.
- Presencia de título del documento.
- Orden de encabezados válido.
- Atributo `lang` presente y con valor válido.
- Estructura correcta de listas y elementos de lista.
- Permiso para ampliar la página mediante zoom.
- Tamaño y espaciado adecuados de objetivos táctiles según la comprobación de Lighthouse.
- Presencia de un punto de referencia principal (`main`).

Las restantes auditorías aprobadas y sus detalles constan en el reporte HTML de Lighthouse generado el 20 de octubre de 2026. No se interpretan las auditorías “no aplicables” como aprobadas o fallidas; simplemente no correspondieron a elementos encontrados o verificables en esa página.

## 4. Comprobaciones manuales pendientes

El reporte enumera diez comprobaciones para las que se requiere inspección manual. Lighthouse no las clasifica como fallos; las presenta para que el equipo las verifique.

| Comprobación sugerida por Lighthouse | Resultado actual | Verificación pendiente |
|---|---|---|
| Controles interactivos enfocables por teclado | Pendiente | Recorrer la página con `Tab` y `Shift+Tab`; confirmar foco visible. |
| Los elementos interactivos expresan su propósito y estado | Pendiente | Revisar navegación, botones, enlaces y cambios de estado. |
| Orden lógico de tabulación | Pendiente | Comparar el orden del foco con el orden visual y funcional. |
| Orden visual coherente con el orden del DOM | Pendiente | Comprobar lectura y navegación asistida. |
| Ausencia de trampas de foco | Pendiente | Entrar y salir de todos los controles y regiones interactivas. |
| El foco se dirige al contenido nuevo cuando corresponde | Pendiente | Revisar mensajes, avisos, diálogos y actualizaciones dinámicas. |
| Contenido fuera de pantalla oculto correctamente a tecnologías de asistencia | Pendiente | Revisar menús, paneles y contenido oculto. |
| Uso de regiones semánticas HTML para navegación | Pendiente | Revisar `header`, `nav`, `main` y `footer` en las vistas relevantes. |
| Etiquetas asociadas a controles personalizados | Pendiente | Revisar nombres accesibles de los controles del sistema. |
| Roles ARIA apropiados en controles personalizados | Pendiente | Inspeccionar árbol de accesibilidad y comportamiento con tecnologías de asistencia. |

## 5. Hallazgos y correcciones

En la página de Inicio, el informe automático no registró fallos en las auditorías automáticas ejecutadas. Las diez comprobaciones manuales permanecen abiertas porque el informe no las puede validar automáticamente y no se ha documentado todavía una prueba manual.

| Criterio o área | Hallazgo confirmado | Componente afectado | Acción / estado |
|---|---|---|---|
| Contraste de color (auditoría automática) | La comprobación automática pasó en la página de Inicio. | Elementos visibles de la página de Inicio evaluados por Lighthouse. | Sin corrección derivada de este informe. |
| Tamaño/espaciado de objetivos táctiles (auditoría automática) | La comprobación automática pasó en la página de Inicio. | Objetivos táctiles evaluados por Lighthouse. | Sin corrección derivada de este informe. |
| Teclado, foco, orden de tabulación y controles personalizados | Lighthouse solicita revisión manual; no es un fallo confirmado. | Navegación y componentes interactivos de Inicio. | Pendiente de prueba manual. |
| Resto de vistas de la aplicación | No están incluidas en el informe adjunto. | Flota, Clientes, Conductores, Pedidos y Rutas. | Pendiente de ejecutar y registrar auditoría por vista representativa. |

## 6. Plan de evaluación restante

1. Repetir Lighthouse con la categoría Accessibility para las vistas principales: Flota, Clientes, Conductores, Pedidos y Rutas. Guardar el reporte o captura de cada ejecución.
2. Realizar pruebas manuales de teclado en los flujos relevantes: navegación por menú, formularios, validación, consulta/filtro de pedidos, asignación de rutas y mensajes de resultado.
3. Inspeccionar con el árbol de accesibilidad los controles interactivos y revisar nombres accesibles, roles, estados y etiquetas.
4. Comprobar zoom/reflow y legibilidad en tamaños de pantalla reducidos; registrar observaciones reales y capturas.
5. Si se detecta un problema, documentar criterio WCAG, página/componente, pasos para reproducirlo, impacto, corrección aplicada y resultado del retest.
6. Al finalizar, actualizar las tablas de este documento y reevaluar los cambios.

## 7. Conclusión

La evidencia disponible para la página de Inicio es favorable: Lighthouse 13.4.1 registró una puntuación de accesibilidad de **100/100**, con 18 auditorías automáticas aprobadas y ninguna auditoría automática fallida en esa ejecución. No obstante, quedan diez comprobaciones manuales y otras vistas por revisar; por tanto, la conclusión se limita a esta ejecución y **no declara conformidad completa con WCAG 2.2 nivel AA para toda la aplicación**.
