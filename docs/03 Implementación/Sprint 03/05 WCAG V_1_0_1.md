## 1. Resumen ejecutivo

Se ejecutó Lighthouse con la categoría **Accessibility** sobre la página de Inicio del frontend de EcoLogística Huancayo.

| Indicador | Resultado observado |
|---|---:|
| Puntuación de accesibilidad de Lighthouse | **100/100** |
| Auditorías automáticas aprobadas | **18** |
| Auditorías automáticas fallidas | **0** |
| Comprobaciones sugeridas para revisión manual | **10** |
| Auditorías no aplicables a esta página | **48** |
| URL evaluada | `http://localhost:5173/` |
| Versión de Lighthouse | `13.4.1` |

El reporte HTML descargado incluye el resultado estructurado de Lighthouse y confirma una puntuación de accesibilidad de `1.0`, equivalente a **100/100**. No se registraron auditorías automáticas fallidas para esta página en esta ejecución.

**Alcance y limitación:** este resultado corresponde únicamente a la carga inicial de la página de Inicio. No es un resultado global de todas las vistas (Flota, Clientes, Conductores, Pedidos y Rutas), y no demuestra por sí solo conformidad completa con WCAG 2.2 nivel AA. Lighthouse advierte que las pruebas automáticas detectan solo una parte de los posibles problemas y recomienda una revisión manual.

## 3. Auditorías automáticas aprobadas

El reporte muestra 18 auditorías aprobadas. Entre las comprobaciones relevantes se encuentran:

- Atributos ARIA compatibles con los roles y con valores válidos.
- Controles de tipo botón con nombre accesible.
- Contraste de color suficiente en los elementos evaluados.
- Presencia de título del documento.
- Orden de encabezados válido.
- Atributo `lang` presente y con valor válido.
- Estructura correcta de listas y elementos de lista.
- Permiso para ampliar la página mediante zoom.
- Tamaño y espaciado adecuados de objetivos táctiles según la comprobación de Lighthouse.
- Presencia de un punto de referencia principal (`main`).

Las restantes auditorías aprobadas y sus detalles constan en el reporte HTML de Lighthouse generado el 20 de octubre de 2026. No se interpretan las auditorías “no aplicables” como aprobadas o fallidas; simplemente no correspondieron a elementos encontrados o verificables en esa página.

## 6. Plan de evaluación restante

1. Repetir Lighthouse con la categoría Accessibility para las vistas principales: Flota, Clientes, Conductores, Pedidos y Rutas. Guardar el reporte o captura de cada ejecución.
2. Realizar pruebas manuales de teclado en los flujos relevantes: navegación por menú, formularios, validación, consulta/filtro de pedidos, asignación de rutas y mensajes de resultado.
3. Inspeccionar con el árbol de accesibilidad los controles interactivos y revisar nombres accesibles, roles, estados y etiquetas.
4. Comprobar zoom/reflow y legibilidad en tamaños de pantalla reducidos; registrar observaciones reales y capturas.
5. Si se detecta un problema, documentar criterio WCAG, página/componente, pasos para reproducirlo, impacto, corrección aplicada y resultado del retest.
6. Al finalizar, actualizar las tablas de este documento y reevaluar los cambios.

## 7. Conclusión

La evidencia automática disponible para Inicio es favorable: Lighthouse 13.4.1 registró 100/100, con 18 auditorías aprobadas y ninguna fallida en esa ejecución. La revisión manual posterior confirmó el foco visible, el orden lógico, el recorrido sin trampa de foco y la activación de enlaces y botones mediante Enter/Espacio según el control. Las demás comprobaciones, otros controles y las vistas adicionales siguen pendientes. Este informe no declara conformidad completa con WCAG 2.2 nivel AA para toda la aplicación.
