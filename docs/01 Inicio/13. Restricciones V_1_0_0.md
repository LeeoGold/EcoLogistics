# 2. Propósito

El presente documento analiza las principales restricciones que condicionan el diseño y desarrollo de EcoLogística Huancayo desde una perspectiva multidimensional.

El análisis considera las dimensiones exigidas por la consigna:

- Salud y seguridad pública.
- Costo del ciclo de vida (LCC).
- Cero carbono neto y sostenibilidad.
- Aspectos culturales, sociales y económicos.

Cada restricción se analiza considerando su impacto sobre el proyecto, la estrategia de mitigación o diseño y las condiciones de cumplimiento que deberán verificarse durante el desarrollo.

El análisis se adapta al contexto de EcoLogística Huancayo sin asumir datos específicos que todavía no hayan sido validados mediante investigación o pruebas.

---

# 3. Criterios de análisis

Para cada dimensión se consideran:

1. **Restricción:** condición que limita o condiciona la solución.
2. **Impacto:** consecuencia probable sobre el proyecto o el producto.
3. **Estrategia de mitigación / diseño:** acción prevista para reducir el impacto.
4. **Cumplimiento / validación:** evidencia necesaria para comprobar que la restricción fue considerada.

# 5. Análisis de impacto por dimensión

## 5.1 Salud y seguridad pública

Las principales restricciones de esta dimensión están relacionadas con la protección de información, el uso correcto de los datos y la necesidad de evitar decisiones de planificación que introduzcan riesgos operativos.

EcoLogística Huancayo deberá aplicar controles de acceso, validación de datos y trazabilidad de operaciones. Las funciones de optimización no deberán considerar una solución válida cuando esta viole una restricción operacional previamente definida.

La arquitectura deberá facilitar la separación entre usuarios y permisos para reducir el acceso innecesario a información.

---

## 5.2 Costo del ciclo de vida (LCC)

El costo de la solución no debe evaluarse únicamente durante el desarrollo inicial.

También deberá considerarse:

- infraestructura;
- mantenimiento;
- evolución;
- monitoreo;
- almacenamiento;
- procesamiento;
- servicios externos.

La selección de Python, FastAPI, React y PostgreSQL favorece una arquitectura modular y compatible con tecnologías de código abierto. La reducción del procesamiento y la optimización de consultas contribuyen a disminuir costos recurrentes.

---

## 5.3 Cero carbono neto y sostenibilidad

El proyecto tiene una doble dimensión ambiental.

### Impacto de la operación logística

La plataforma busca reducir:

- distancia;
- combustible;
- emisiones;
- recorridos innecesarios.

### Impacto del propio software

El sistema también debe evitar consumo computacional innecesario.

Por ello se considerarán:

- consultas optimizadas;
- transferencia limitada de datos;
- procesamiento controlado;
- reducción de operaciones redundantes;
- arquitectura que permita asignar recursos según necesidad.

Los indicadores ambientales deberán utilizar datos y supuestos documentados para evitar conclusiones incorrectas.

---

## 5.4 Aspectos culturales, sociales y económicos

EcoLogística Huancayo deberá considerar que los usuarios pueden tener diferentes conocimientos tecnológicos y diferentes necesidades de interacción.

La interfaz deberá adaptarse a los perfiles definidos en el documento 08:

- Administrador.
- Operador logístico.
- Conductor.
- Cliente / Usuario final.
- Auditor.

El modo conductor tendrá especial prioridad debido a que debe presentar solamente la información necesaria para ejecutar la ruta y consultar las entregas.

La priorización del MVP también será una medida de control económico y académico, evitando ampliar el alcance sin capacidad suficiente para desarrollarlo y probarlo.

# 6. Matriz de severidad

| Nivel | Criterio |
|---|---|
| **Crítica** | El incumplimiento puede comprometer seguridad, integridad de datos, cumplimiento normativo o una condición esencial del MVP. |
| **Alta** | El incumplimiento puede afectar significativamente el funcionamiento, costo, calidad o aceptación del sistema. |
| **Media** | El incumplimiento puede generar retrabajo, menor eficiencia o deterioro de la experiencia. |
| **Baja** | El incumplimiento tiene un impacto limitado y puede gestionarse durante una iteración posterior. |

# 8. Estrategias de mitigación transversal

## 8.1 Seguridad y privacidad

- Autenticación y autorización.
- Mínimo privilegio.
- Validación de entradas.
- Registro de operaciones relevantes.
- Limitación de acceso a información personal.

## 8.2 Costos

- Uso prioritario de tecnologías de código abierto.
- Optimización de consultas.
- Separación de componentes.
- Evaluación periódica del consumo de recursos.

## 8.3 Sostenibilidad

- Medición de emisiones.
- Comparación con escenario base.
- Optimización de procesamiento.
- Reducción de transferencias y operaciones innecesarias.

## 8.4 Factores sociales

- Diseño por perfiles.
- Modo conductor.
- Lenguaje claro.
- Pruebas de usabilidad.
- Validación progresiva con usuarios.

## 8.5 Gestión del alcance

- Priorización del MVP.
- Desarrollo incremental.
- Control formal de cambios.
- Revisión al final de cada iteración.

# 13. Control y actualización

El análisis de restricciones será revisado durante cada iteración del proyecto.

Una restricción podrá:

- confirmarse;
- modificarse;
- reducir su severidad;
- aumentar su severidad;
- convertirse en un riesgo;
- generar una nueva decisión arquitectónica.

Toda modificación significativa deberá analizar su impacto sobre requisitos, reglas de negocio, usuarios, arquitectura, base de datos y pruebas.

---

# 14. Criterios de aceptación del análisis

El presente análisis será considerado completo cuando:

- Las cuatro dimensiones exigidas por la consigna estén documentadas.
- Cada restricción tenga impacto identificado.
- Cada restricción tenga una estrategia de mitigación o diseño.
- Exista una condición de cumplimiento o evidencia verificable.
- Las restricciones estén relacionadas con requisitos y arquitectura.
- Se mantenga trazabilidad con las reglas de negocio.
- El registro pueda actualizarse durante las iteraciones.

---

# 15. Conclusión

EcoLogística Huancayo se encuentra condicionado por factores de seguridad, costo, sostenibilidad y características culturales, sociales y económicas.

El análisis multidimensional permite que estas restricciones sean consideradas desde las primeras etapas de diseño y no únicamente cuando el sistema se encuentre implementado.

La estrategia propuesta busca reducir el impacto de las restricciones mediante controles de seguridad, arquitectura modular, optimización de recursos, medición ambiental, diseño centrado en los usuarios y control del alcance.

De esta manera, las restricciones se convierten en criterios explícitos para orientar las decisiones de diseño, desarrollo y validación de EcoLogística Huancayo.

La versión inicial del presente documento corresponde a **V_1_0_0**.
