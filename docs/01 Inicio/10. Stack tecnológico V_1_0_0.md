## 2. Propósito

El presente documento evalúa alternativas de stack tecnológico para EcoLogística Huancayo mediante criterios multidimensionales relacionados con curva de aprendizaje, infraestructura, soporte, eficiencia energética, adecuación al proyecto y escalabilidad.

La consigna exige evaluar al menos tres alternativas y realizar una justificación técnica formal de la combinación seleccionada.

## 6. Análisis de alternativas

### 6.1 MERN

MERN presenta una curva de aprendizaje favorable cuando existe experiencia previa con JavaScript y permite desarrollar frontend y backend alrededor de un ecosistema común. React facilita una interfaz modular y Node.js/Express permite construir servicios web.

Sin embargo, EcoLogística Huancayo maneja entidades y relaciones entre pedidos, vehículos, conductores, clientes y rutas que pueden representarse de manera natural con un modelo relacional. Además, el proyecto requiere un componente de optimización que puede beneficiarse de un entorno orientado al análisis y experimentación algorítmica.

**Valoración:** alternativa viable, pero no la de mayor adecuación global.

### 6.2 Python / FastAPI + React + PostgreSQL

Python es especialmente conveniente para implementar y experimentar con el motor de optimización. FastAPI permite construir los servicios de la aplicación y React permite desarrollar una interfaz modular.

PostgreSQL resulta apropiado para representar relaciones entre usuarios, vehículos, conductores, clientes, pedidos, rutas y asignaciones.

Esta alternativa presenta un equilibrio favorable entre capacidad técnica, infraestructura, escalabilidad y necesidades del proyecto.

**Valoración:** alternativa con mayor adecuación global.

### 6.3 Java Spring Boot + Angular + PostgreSQL

Spring Boot, Angular y PostgreSQL constituyen una alternativa sólida para sistemas empresariales y de gran escala. Sin embargo, para el MVP académico puede representar una mayor complejidad inicial y una demanda de infraestructura superior a la necesaria.

**Valoración:** técnicamente sólida, pero menos conveniente para el alcance inicial del MVP.

## 7. Selección del stack

### Stack seleccionado

**Python / FastAPI + React + PostgreSQL**

Arquitectura base:

```text
React
  |
  | HTTP / JSON
  v
FastAPI
  |
  +--> Lógica de aplicación
  |
  +--> Motor de optimización
  |
  v
PostgreSQL
```

Para mapas se considera Leaflet/OpenStreetMap, de acuerdo con las orientaciones tecnológicas del proyecto.

## 8. Justificación técnica formal

La combinación Python / FastAPI + React + PostgreSQL presenta la mayor adecuación para EcoLogística Huancayo por las siguientes razones.

### Escalabilidad

La separación entre frontend, backend, motor de optimización y persistencia permite ampliar cada componente según sus necesidades de carga.

### Perfil del proyecto

Python facilita la implementación y evaluación de metaheurísticas para el problema de ruteo. React permite construir interfaces diferenciadas por perfil de usuario y PostgreSQL representa adecuadamente la información relacional del dominio.

### Eficiencia energética

Se priorizará el procesamiento necesario, consultas optimizadas, reducción de transferencia de datos y evitación de operaciones redundantes. Esto permite aplicar criterios de Green Software en el diseño.

### Adecuación al MVP

La combinación permite desarrollar el producto progresivamente, manteniendo separadas las responsabilidades y facilitando pruebas, mantenimiento y evolución.

## 11. Riesgos tecnológicos

| Riesgo | Mitigación |
|---|---|
| Brechas de conocimiento | Distribución de responsabilidades y aprendizaje progresivo. |
| Complejidad del algoritmo | Separar el motor de optimización de la API y probarlo de forma independiente. |
| Crecimiento del volumen de datos | Modelo de datos consistente y diseño escalable. |
| Dependencia de servicios cartográficos | Mantener alternativas para carga de datos geográficos. |
| Consumo excesivo de recursos | Optimizar consultas, procesamiento y transferencia. |

## 12. Conclusión

Después de comparar tres alternativas, se selecciona **Python / FastAPI + React + PostgreSQL** como stack tecnológico de EcoLogística Huancayo.

La decisión se fundamenta principalmente en la adecuación al problema de optimización, el carácter relacional de la información logística, la posibilidad de desarrollar el MVP de manera incremental, la capacidad de crecimiento y la aplicación de criterios de eficiencia energética.

La decisión deberá validarse durante las etapas posteriores mediante pruebas de integración, rendimiento y mantenibilidad.
